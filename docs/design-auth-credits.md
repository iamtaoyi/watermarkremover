# 设计方案：登录体系（手机号 / 微信）+ 积分充值

> 状态：**待确认，未实现**
> 目标：登录页支持手机号注册登录、微信快捷登录（需绑手机）、微信充值积分。

## 一、三个硬前提（资质，不是技术）

| 能力 | 依赖资质 | 现状 | 卡点 |
| --- | --- | --- | --- |
| 手机号验证码登录 | 短信服务（阿里云/腾讯云 SMS）+ **短信签名与模板审核** | 无 | 签名审核通常要求**已备案网站/APP**或商标 |
| 微信快捷登录 | 微信开放平台**网站应用**（300 元认证）+ **授权回调域必须已备案且 HTTPS** | 无 | 域名 `theinward.cn` 未备案、站点是 HTTP |
| 微信充值积分 | **微信支付商户号**（企业）+ 备案域名 + 微信认证 | 无 | 同上 |

结论：**ICP 备案是所有微信/短信能力的前置**。备案完成前只能做"不依赖微信/短信"的部分（见第六节 P1）。

## 二、登录方式设计

### A. 手机号 + 验证码（注册即登录）
- `POST /api/auth/sms/send { phone }`
  - 同一手机号 60 秒内只能发一次；每号每日 ≤10 条；每 IP 每小时 ≤20 条
  - 需要图形验证码/滑块，防止短信轰炸（短信按条计费，被刷就是真金白银）
- `POST /api/auth/verify { phone, code, bindToken? }`
  - 验证码 6 位、5 分钟有效、一次性
  - 手机号不存在 → 自动注册（`users` 新记录，赠初始积分）
  - 返回 `sessionToken`（Bearer）+ HttpOnly Cookie（网页用 Cookie，小程序用 Bearer）

### B. 微信快捷登录（网站扫码）
- 微信开放平台「网站应用」OAuth2：`snsapi_login`
- 流程：前端展示二维码 → 用户扫码授权 → 回调 `code` → 服务端换 `access_token`/`openid`/`unionid`
- **首次登录必须绑定手机**：拿到 unionid 后若无手机号 → 返回一次性 `bindToken` → 前端走 A 的验证码流程绑定
- 小程序端：`wx.login` → `code2session` → 用 **unionid** 关联同一 `users` 记录（同一人网站/小程序同一个账号）

### C. 管理员 Token 登录（保留）
- 环境变量 `ALLOW_ADMIN_TOKEN=1` 时保留现有 Token 入口，仅用于内部应急/运维
- 默认关闭，避免与真实用户体系混用

## 三、数据模型

```js
users: {
  u_xxx: {
    id, phone, phoneVerifiedAt,
    wechat: { openid, unionid, nickname, avatar },
    credits: 120,                       // 余额（整数，单位：积分）
    role: 'user' | 'admin',
    status: 'active' | 'banned',
    createdAt, lastLoginAt
  }
}
creditLedger: [                          // 只追加，永不修改 —— 对账依据
  { id, userId, delta: -12, reason: 'task:task_xxx', balanceAfter: 108, at }
]
orders: {
  o_xxx: { id, userId, credits, amountFen, channel: 'wechat'|'card',
           status: 'pending'|'paid'|'closed'|'refunded',
           wxPrepayId, wxTransactionId, paidAt, createdAt }
}
redemptionCodes: { code: { credits, usedBy, usedAt, batch } }   // 过渡期卡密
sessions: { sid: { userId, createdAt, expiresAt } }             // 从"单 Token"改为"用户会话"
```

**归属改造（必须）**：`batches` 与 `tasks` 增加 `userId`；所有列表/操作按归属过滤。当前批次是全局的（49 个批次无归属），需要一次性回填给管理员账号。

## 四、积分与计费

- **计费口径**（三选一，见第七节决策 1）
- **先扣后用，失败退还**：提交时扣，任务失败/取消全额退回（写 `refund` 账本）
- **并发限制**：每用户同时处理 ≤3 个，防刷
- **余额不足**：拦截提交，提示充值
- **充值比例**：1 元 = 10 积分（可调）；初始化 1 元 = 10 积分 ≈ 覆盖一次 5 分钟视频的处理成本（需按真实账单校准）

## 五、微信支付充值（备案后）

- 网站 PC：微信支付 **Native**（二维码）；微信内打开：**JSAPI/H5**
- 流程：创建订单(pending) → 统一下单拿 `code_url`/`prepay_id` → 前端展示二维码/拉起支付 → **notify 回调验签** → 幂等置 paid → 写账本加积分 → 前端轮询订单
- 必备：回调幂等、订单超时关闭（2 小时）、每日对账、退款接口
- 合规：虚拟商品明示"积分不可提现/不可退款"、发票流程、未成年人限制、隐私政策与用户协议
